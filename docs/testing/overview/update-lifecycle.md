# 更新生命周期测试模型

> 本文件只描述经验证的产品生命周期。初始化阶段不假设具体内部状态名。

## 1. 目的

把更新测试从“点按钮”提升为“验证生命周期”。

新的测试人员或 AI 应能通过本文件快速判断：

- 当前更新处于哪个阶段；
- 每个阶段应该观察什么；
- 什么结果允许进入下一阶段；
- 哪些失败会阻断后续阶段；
- 哪些阶段可以独立验证。

## 2. 通用测试视角

在产品细节补全前，使用下面的抽象视角组织测试：

```text
准备 / 前置检查
      ↓
获取更新信息
      ↓
下载 / 获取更新内容
      ↓
安装 / 部署
      ↓
需要时重启
      ↓
升级后验证
      ↓
必要时回退
      ↓
回退后验证
```

这只是测试组织模型，不代表产品内部一定存在同名状态。

## 4. 每个阶段至少回答

- 如何确认已经进入该阶段？
- 成功时看什么？
- 失败时最小证据是什么？
- 等待多久/出现什么条件后应认为没有进展？
- 是否存在稳定 fallback？
- 当前阶段失败后还有哪些独立测试可继续？

## 5. 生命周期与 Playbook

本文件保存共性的阶段模型；具体测试场景保存在 `../playbooks/`。

例如同一个“安装”阶段可能出现在在线更新、离线更新、中断恢复等多个 Playbook 中，不要在每个 Playbook 重复解释通用概念。

## 6. 变更规则

发现新的生命周期行为时：

1. 首次观察写入 `LEARNINGS.md`；
2. 复现或取得明确证据；
3. 确认是跨场景稳定行为后更新本文件；
4. 如果只影响一个具体场景，则只更新对应 Playbook。
